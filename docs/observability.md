# Audit log and metrics

## Audit log

ulgen logs as every infrapi/lib service (`INFRAPI_APP_LOG_FORMAT`,
`INFRAPI_APP_LOG_LEVEL`). Each tool call is one `tool call` line:

| Field | |
|---|---|
| `user` | the caller, as Kayra resolved them |
| `api`, `tool` | what was called: the API, and the tool under its own name |
| `namespace` | the call's `namespace` argument, when it has one |
| `outcome` | `ok`; `tool_error`, an error result of the API's (its refusal included); `error`, the API unreachable |
| `duration_ms` | the call's duration |
| `request_id` | the request's `X-Request-Id` |

```json
{"level":"info","msg":"tool call","user":"jdoe","api":"compute.infrapi.io","tool":"get_vm","namespace":"acme","outcome":"ok","duration_ms":38,"request_id":"5f0c9a7e-…"}
```

Every request is also in infrapi/lib's access log.

## Following a request

`request_id` is the request's `X-Request-Id`, set by the gateway in front,
or generated by ulgen. ulgen passes it on to the API it calls, with the
caller's `Traceparent`: one request is followed through the gateway's,
ulgen's and the API's logs and traces.

## Metrics

`<root>/-/metrics`, as every infrapi/lib service: the HTTP requests
(`http_requests_total`, `http_request_duration_seconds`), the Go runtime's
and the process's, and ulgen's:

| Metric | Labels |
|---|---|
| `ulgen_tool_calls_total` | `api`, `tool`, `outcome` (as in the audit log) |
| `ulgen_tool_call_duration_seconds` | `api`, `outcome` |
| `ulgen_kayra_request_duration_seconds` | `op` (`apis`, `namespaces`), `result` (`ok`, `refused`, `error`) |
| `ulgen_tools_served` | `api`: the tools served, as last listed |
| `ulgen_tools_list_errors_total` | `api` |
| `ulgen_build_info` | `version` |

```promql
# calls per second, per API and outcome
sum by (api, outcome) (rate(ulgen_tool_calls_total[5m]))

# an API that stopped listing its tools
increase(ulgen_tools_list_errors_total[15m]) > 0

# callers refused a token: the MCP endpoint's 401s
sum(rate(http_requests_total{path=~".*/-/mcp.*", status="401"}[5m]))
```
